# Screen layout v1

Query anyapi.screen_layout version 1 and validate AnyScreenLayoutV1 size/version. available() indicates the guarded native hook is installed. set_offset(screen_id, ui_state, x_fraction, y_fraction) registers a plugin-owned contribution to a named native root screen. Fractions are finite and bounded to ±0.25; state is 0–127. Set both offsets to zero to restore the original position. At most 32 owner/screen/state entries are retained. Contributions from active owners add together and clamp to ±0.25 of the native viewport.

The host calls the exact native screen_layout implementation first, then offsets its root origin at screen+0x78/0x80 using native UI viewport dimensions at ui+0x90/0x98. The signed translation can move a full-viewport root to a negative origin; only offset fractions are bounded. Clamping the resulting origin to zero previously suppressed leftward movement. Reviewed native screen.render and get_element_by_screen_position both use that root origin, keeping drawing and hit testing aligned. Font, native scale and child layout are unchanged. The hook steals 21 complete instructions without RIP-relative operands. All three native bodies must match exactly before installation.

AnyInventory owns the policy: screens ui_aligner, portrait_aligner and ui_aligner_tooltip in inventory state 2 are shifted away from its sidebar. Other screens/states remain unaffected. API consumers should restore offsets when hidden and on shutdown. Inactive/faulted owners stop contributing. See anyapi_screen_layout.inc and INVENTORY_ACTION_CONTRACTS.json. Automated tests cover owner aggregation, inactive owners, state scoping, limits, zero-origin negative translation and restoration; live visual/hit alignment remains user validation.

native borrowed screen IDs (GeoString16 capacity zero) are valid. Safe reads use bounded length; nonzero owned capacity still must cover length. The realistic native regression uses the borrowed representation observed in the running crate screen. Native coordinates are normalized UI units; percentage offsets use that native viewport, not assumed pixels. SCREEN_LAYOUT applied=1 logs only after an actual matched root translation, once per distinct requested offset. Hook readiness alone does not establish live layout acceptance.
