# Inventory actions v1

Query anyapi.inventory_actions version 1, validate AnyInventoryActionsV1 size/version, then check available(). add_one(stable_definition_id) returns a ticket, or 0 when unavailable, unknown or queue-full. state(ticket) returns UNKNOWN, QUEUED, SENT, EXPIRED or FAILED. SENT records native event submission only; no server receipt/placement acknowledgement is exposed.

Requests bind to a recently sampled local scene while inventory UI state 2 is open. At most eight requests are pending, with 64 retained statuses. They expire after two seconds, on observed inventory closure, or a changed sampled scene. The existing guarded player-tick callback dispatches at most one per invocation; consumed requests are never retried. A native exception disables this action service and logs it.

The exact installed client_scene.update_ui_settings dependency table locates get_definition_by_id_const at 0xd068 and push_event_inventory_debug_give_item at 0xd0b0. The definition container is scene+0x1530, numeric ID is definition+0x408 and peer data is client+0x90. Native arguments are passed by reference: definition ID, component -1, colour 0 and empty filter. The native server creates one instance and runs its normal inventory pickup. Full inventory can leave an item in the world; authored default stacks remain native. No direct server inventory writes are performed. Host-only live testing is pending; joining-client permissions/rejection are not verified.

INVENTORY_ACTION_CONTRACTS.json pins native signatures, bodies and dependency identities to v0.1.21 / Steam 25725299. inventory_native_test.cpp executes the exact Give-event body with controlled native imports and verifies allocation, construction, push, destruction, ticket states and cancellation. Logs use INVENTORY_ACTION with ticket, stable ID and server_confirmation=NOT_OBSERVED.

## Version 2: caller-owned mode restrictions and components

Query anyapi.inventory_actions version 2 and validate AnyInventoryActionsV2. v1 provides available/state; add_one(id, allowed_modes) accepts a bit mask of normalized AnySessionMode values. The host checks a recent anyapi.session sample before queuing and again before dispatch. A changed or unknown mode expires a restricted request without sending it. AnyInventory uses ANY_MODE_MASK_CREATIVE_SANDBOX; the base API exposes generic policy rather than hardcoding the mod's modes. The v1 unrestricted request remains for ABI compatibility.

component:<id> resolves through the exact native component lookup dependency at 0xd0e8, scene+0x15d8, numeric component ID at +0x290. The native inventory wrapper is vehicle_editor_add_component, or vehicle_editor_add_building_component for building categories. The event receives wrapper inventory ID and numeric component ID, preserving native pickup behavior. No fabricated inventory IDs or direct save edits are used. Tests execute the native event body with both item and component arguments, mode transitions, expiry and rejected requests.
