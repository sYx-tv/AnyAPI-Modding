## Extending this system

| Question | Status | Mechanism / reason |
|---|---|---|
| Observe an event | **needs_validation** | cell_hook on server.handle_message / client.handle_message and on_network_event. |
| Change a value or behaviour | **needs_validation** | Server-side state changes replicate automatically if they go through replication.master property setters or set_modified. |
| Create and destroy objects | **not_applicable** | - |
| Register a new definition or implementation | **closed** | Message types (messages_*.e_type) and replicated object types are closed enums; unknown ids would desync or disconnect vanilla peers. |
| Attach custom behaviour/data | **unresolved** | Chat messages are the only free-form string channel both ways; using them for mod data would be visible to vanilla players and is not recommended. |
| Persist custom state | **not_applicable** | - |
| Replicate custom state to other players | **closed** | No mod channel in the protocol. A separate mod transport (own socket/Steam P2P channel) is outside the game. |
